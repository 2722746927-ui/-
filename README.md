# 人生规划 · Life Planner AI

通过三轮访谈理解个人价值观、生活诉求和现实条件，在三轮信息收集后，生成四阶段人生发展规划。V1 免费体验，访谈无需账号，无支付或访谈数据库。

## 当前实现

- 第一轮 6 个基础问题；第二、三轮由 DeepSeek 基于全部已回答内容动态生成 1—5 个问题。
- 分步单选、多选、自由输入，支持不知道、跳过、返回修改。修改早期回答后清除后续追问和旧报告，重新生成。
- 服务端 JSON 输出校验、一次格式修复、超时和明确错误重试，不以模板报告冒充真实 AI 结果。
- 四阶段报告，区分用户事实、合理推测与待验证信息，并可展开查看原回答依据。
- 浏览器本地会话恢复、隐私同意、清除数据。
- 中文 PDF 文件下载：内置 SIL OFL 的 Noto Sans SC 字体，真实文字、自动分页；同时支持浏览器打印。
- 手机优先蓝白中文界面。

## 本地运行

需要 Node.js 20.9+（开发环境已使用 Node.js 24）。

```bash
npm ci
cp .env.example .env.local
# 在本机编辑 .env.local，填写自己的 DEEPSEEK_API_KEY
npm run dev
```

访问 http://localhost:3000。`.env.local` 已被 Git 忽略。密钥只能放服务端，不得使用 `NEXT_PUBLIC_` 前缀，也不要把密钥写在聊天、README 或 GitHub。

环境变量：

| 名称 | 用途 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 必需，DeepSeek API 密钥 |
| `DEEPSEEK_MODEL` | 可选，默认 `deepseek-flash` |
| `DEEPSEEK_BASE_URL` | 可选，默认 `https://api.deepseek.com`，不带末尾斜杠 |

未配置密钥时，首页会显示准备中，第一轮可以填写；服务端返回明确的未配置提示，不会生成虚构规划。

## 部署方案 A：Vercel（原生 Next.js）

1. 在 Vercel 导入此 GitHub 仓库，Framework 选择 Next.js。
2. 在项目 Settings → Environment Variables 中添加 `DEEPSEEK_API_KEY`，可选 `DEEPSEEK_MODEL`。
3. 部署。路由 `/api/planner` 运行于服务端，`/api/health` 仅返回是否已配置，不返回密钥。
4. 函数已声明 `maxDuration = 300`；请确认套餐允许足够的函数运行时间。每次模型请求超时为 115 秒，格式修复最多再调用一次。
5. 发布前在平台启用访问频率与预算限制；无账号的公开 AI 服务仍可能被滥用。

## 部署方案 B：Sites / Cloudflare Worker

项目保留原生 Next.js 实现。`npm run build:sites` 会在忽略的 `work/` 内构建前端静态副本，再将同一个服务端规划处理器与压缩静态资源编译为 `dist/server/index.js`，不会将密钥编进静态文件。

`.openai/hosting.json` 记录 Sites 项目身份；在 Sites 的服务端运行环境中将 `DEEPSEEK_API_KEY` 配置为 secret，重新部署后生效。默认部署可先私有预览；用于真实体验时按产品访问设置开放访客访问。

Worker 包含基于平台 IP 的单实例尽力限流（15 分钟 15 次，最多 2 个并发）。这不是全局额度保护；公开运营仍需平台级限流、费用上限与监控。

## 数据和隐私

本版本不把访谈或报告写入网站数据库，也不在应用代码中打印用户回答。回答及报告仅在当前浏览器 localStorage 保存；生成追问或报告时，全部现有访谈经服务端发送给 DeepSeek，服务方和托管平台按各自政策处理数据。不要收集身份证、精确地址、联系方式等无关信息。

清除本次数据只清除本机副本，无法撤回已发往模型服务的数据。共享设备、无痕模式和浏览器清理有各自风险；下载的 PDF 由用户自行保存。

- `src/lib/session.ts`：本机状态恢复与回答修改失效逻辑。
- `src/lib/pdf.ts`：中文字体嵌入与分页导出。
- `scripts/`：可选 Sites 构建适配器。
- `tests/`：核心流程与 PDF 自动化测试。

## 已知边界

AI 事实真实性仍需要人类审阅，编号校验不等同于验证自然语言结论。模型可能偶尔重复语义相近的问题；当前拦截完全重复的问题及错误结构。V0.1 没有跨设备恢复、账号、历史报告或后台。浏览器语音输入暂未开发，所有问题都保留文字输入。报告不提供心理诊断，不承诺就业、收入或升学结果。

PDF 支持字体覆盖内的中文、拉丁字母和常用符号；不支持的表情或罕见字符会替换为问号，网页保留原文。字体来源与许可见 `public/fonts/OFL.txt`；Noto Sans SC 为 SIL Open Font License 1.1。

## 不接 API 时可以体验什么

首页可打开“查看示例报告”，浏览并下载一份人工编写的完整虚构样本。网页、PDF 文件名和 PDF 每页页眉均标记示例；它不使用访客回答，不调用模型，也不会覆盖已保存的规划。

第一轮可以填写、自动保存、回看和修改。服务未准备好时不发送分析请求，而是保留回答并提示稍后继续。回答总览可导出本地 JSON 备份，首页可恢复备份；恢复前需要确认覆盖，恢复后重新取得 AI 分析同意。备份包含个人回答与报告，请勿公开上传。

手机报告页面提供可展开的目录与回答依据。PDF 下载有加载提示、字体请求超时和重试，失败时可用打印保存。隐私、清除、恢复及回答总览弹窗支持 Escape 退出、焦点约束与关闭后返回原操作位置。当前输入会保留；发现损坏的旧记录时暂停覆盖，直至用户明确重置或恢复备份。

## 三轮完整流程演示

首页“完整流程演示 · 无需 API”或网址参数 `?demo=1` 可进入独立演示。可逐题完成三轮，也可直接切换第二、三轮；最后展示明确标注的虚构示例报告，不依据输入生成个人结论。第二、三轮为预设示例问题，不能代表真实 AI 的动态追问效果。

真实第一轮完成但服务尚未准备时，可点击“继续体验第二、三轮（演示）”，直接从演示第二轮继续。正式回答保持原样，演示进度使用单独的 `life-planner.demo.v1` 本机存储，刷新可恢复。退出演示回到原页面；重置演示会清空其输入；“清除本次数据”同时清除正式与演示数据。

## DeepSeek 网站所有者配置入口（Sites 部署）

访问 `/admin/deepseek`，通过平台提供的 ChatGPT 登录确认身份后，只需填写 DeepSeek API Key，点击“保存并连接 DeepSeek”。服务端会使用官方 `/models` 获取实际模型列表，优先选择 `deepseek-flash`，再用一次极小的真实 JSON 模型调用验证可用性，随后以 AES-256-GCM 加密保存到私有 R2 绑定 `CONFIG_BUCKET`，立即供公开规划接口使用，无需重新部署。

- 首次配置身份只允许 `PLANNER_OWNER_EMAIL` 对应的平台已验证账号；首次成功保存后记录站点专属用户 ID，后续操作只接受该 ID。
- `PLANNER_OWNER_EMAIL` 与随机 256 位 `PLANNER_SECRET_KEY` 通过 Sites 原生服务端 secret 设置，不进入 Git、前端或浏览器存储。不要删除或轮换加密根密钥，否则无法解密已保存的 API Key；需要轮换时须安排重新录入或迁移。
- R2 只保存加密的站点 API 凭据及所属站点用户 ID、更新时间，不保存用户访谈和规划报告。原有访谈仍在浏览器本地保存。
- 管理 API 强制身份验证、已绑定所有者检查、同源请求、HMAC 防跨站令牌、输入大小和频率限制。API Key 及其片段均不从接口返回，也不写日志；验证失败不替换原配置。
- 匿名访客可以看到管理页的登录提示，但无法读取配置状态、显示密钥表单或修改配置。公开规划服务仍不要求用户注册。
- R2 缺失、加密设置缺失、密文被篡改时拒绝保存/读取，不使用不持久的内存保存冒充成功。
- 原生 Next.js/Vercel 的 `DEEPSEEK_API_KEY` 环境变量模式保留；此浏览器管理入口的持久保存需要 Sites 提供的 R2 与身份注入，不能直接搬到没有这些绑定的平台。

连接验证包含一次 32 token 输出上限的小型真实模型调用，可能产生少量 API 费用；真实访谈的内容质量仍需通过实际体验验证。

## DeepSeek 连接故障修复与诊断

Cloudflare Workers / workerd 不支持 Fetch 的 `redirect: "error"`。所有服务端 DeepSeek 调用统一通过 `src/lib/deepseek-http.ts`，使用 `redirect: "manual"`，显式拒绝 HTTP 3xx，因此既兼容线上运行时，也不会把 Authorization 跟随重定向发送到其他地址。

设置页会显示脱敏的错误编号、失败阶段、网站 HTTP 状态和（实际收到时的）DeepSeek HTTP 状态。分别处理 DNS、TLS、连接拒绝/重置、超时、401 鉴权、402 余额、403 权限、404 接口、429 限流、5xx 网关、HTML/损坏 JSON、模型权限与存储写入错误。未知网络错误只说明“尚未收到有效响应”，不猜测密钥有效性。

不返回或记录提供商的原始响应体、请求 Authorization、API Key、异常堆栈或包含凭据的错误文本。诊断信息只由固定枚举与数字状态组成。验证通过才尝试加密写入；验证失败保留旧配置。临时防跨站令牌过期时仅刷新令牌并重试一次，普通连接/保存故障不自动重复提交。

## 动态选择并验证当前 DeepSeek 模型

密钥保存流程不再要求旧 ID `deepseek-chat` / `deepseek-reasoner` 必须存在。服务端先读取实际 `/models` 列表，优先选择 `deepseek-flash`；若没有 Flash，则在列表内选择已配置且支持文本的模型、`deepseek-v4-pro` 或其他实际返回的文本模型，不捏造模型 ID。

随后仅执行一次最小真实 `/chat/completions` 调用，关闭 thinking、启用 JSON 输出、限制 `max_tokens: 32`，要求完整返回 `{"ok":true}`。HTTP 200、仅有模型列表、空最终内容、截断、无效 JSON、拒绝请求或账户余额问题，都不能算验证成功，也不会保存新密钥。

验证成功后，将 API Key、通过验证的模型 ID 和验证时间一起加密保存。模型 ID 可在所有者设置页查看，但 API Key 不返回。追问与报告读取这个已验证模型，优先级高于可能过时的环境变量；所有真实生成使用与验证相同的非思考 JSON 配置。兼容读取过去的加密密钥记录，新的默认模型为 `deepseek-flash`。

- https://api-docs.deepseek.com/api/list-models/
- https://api-docs.deepseek.com/api/create-chat-completion/
- https://api-docs.deepseek.com/guides/thinking_mode/

## V1 核心逻辑：三轮收集，四阶段规划

三轮问答不对应三个分析阶段：

1. 基础了解：当前阶段、兴趣、价值观、能力、资源和现实条件。
2. 个性化探索：根据已有回答补足少量关键缺口，并开始探索未来生活；未来主题问题至少占一半。
3. 未来方向澄清：理想生活、重要选择、愿意探索的方向和现实取舍；未来主题至少占三分之二，不再以画像盘问为主。

`prompts.ts` 给出分轮专用指令，生成问题必须标注 `topic`。服务端按轮校验主题比例；不符合时进入同一个有界修复流程，不用固定问卷冒充动态追问。此结构校验不能替代对实际自然语言质量的评估。

三轮结束后才生成 `reportVersion: 2` 报告，网页与 PDF 使用相同四阶段顺序：

- 认识自己：原有画像、证据、核心需求和现实条件。
- 明确未来想要的生活：理想生活、目标、取舍、未知问题与可能方向。
- 倒推个人发展路径：优先方向、长期到近期的路径、30天行动、进展和风险调整。
- 建立内在行动动力：新增必填 `motivation`，逐项将近期行动关联到未来生活、长期目标、个人价值和优先级，并给出受阻时的可选最小行动、调整与暂停标准。

第四阶段必须覆盖全部行动（从0开始的 `actionIndex`，恰好一次），非未知判断必须引用有效访谈依据。愿景未知时可以明确标为 `unknown`，任务意义可以是探索和获取选择依据，不强行生成职业或十年目标，也不用焦虑与羞耻推动行动。报告输出预算与问答分开设置，以容纳完整四阶段内容。

存储键和备份格式保留，已填写的旧访谈不会丢失。旧六章报告可按四章回看并导出，但第四阶段明确标注尚未生成，需基于访谈重新生成；不会自动把旧报告“升级”为未经AI分析的个人动机。新的不完整 v2 报告不能降级成旧格式绕过校验。旧版演示在更新题目时保留原问题和回答以供回顾，演示仍不调用AI。

主要修改：`workflow.ts`、`questions.ts`、`prompts.ts`、`schema.ts`、`server.ts`、`session.ts`、`planner.tsx`、`report.tsx`、`pdf.ts`，以及对应演示、示例与测试。DeepSeek模型发现、真实最小调用验证、密钥加密存储和所有者权限逻辑保持不变。

若本机安装了 Poppler 的 `pdftotext`，PDF测试还会提取中文并验证四阶段顺序及行动意义；未安装时仅跳过文本提取检查，其余PDF和交互测试照常执行。

### 正在填写的旧问卷升级

页面顶部显示“四阶段规划新版已上线”。浏览器恢复旧问卷时不会擅自替换已生成的问题；用户可点击“保留回答，切换新版问卷”。相同基础题沿用原回答，只补缺少的问题，并重新生成后续轮次。旧题目、回答及旧报告保留在本地备份和“回看回答”中。历史问答以 `previous.rN.questionId` 提供给 AI 作为背景，新回答优先；报告证据支持追溯历史原文。清除本次数据会同时清除这些本机记录。
